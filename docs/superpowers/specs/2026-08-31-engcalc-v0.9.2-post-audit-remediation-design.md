# EngCalc 0.9.2 Post-Audit Remediation Design

## Status

Approved for implementation from the independent 0.9.2 re-audit supplied by the user on 2026-08-31. This work starts from `main@a1dc97b40df64a1e351f1957bd910cde0232a38e` and runs on `fix/v0.9.2-post-audit-remediation`.

## Goal

Correct the four defects discovered by the independent re-audit without beginning the deferred 0.9.3 exact-envelope work, and close the coverage gaps that allowed the defects to survive a fully green 884-test suite.

## Release/version constraint

The package version remains `0.9.2` during remediation. A corrective release number is not chosen until all defects are reproduced, fixed, and the complete verification matrix is green. `0.9.3` remains reserved by the roadmap for Exact Envelopes / Governing Intervals unless explicitly changed later.

## Authoritative audit findings

### N-1 — CRITICAL — decimal roots can disappear silently

Natural reproduction:

```text
f(x) = 2.87*x^2 + -12.50459*x + 6.4876637
roots(f(x), x, 0, 5)
```

Expected roots: approximately `0.602` and `3.755`.

Observed audit mechanism: `sympy.solveset(..., domain=S.Reals)` can return `EmptySet` for expressions containing `Float` coefficients. `_exact_real_solution_set()` marks `EmptySet` complete, so `_solve_continuous_zero_set()` suppresses deterministic fallback even though `_fallback_roots()` can recover the roots.

Required behavior:
- no false empty root set for realistic decimal polynomials;
- exact-first semantics remain intact;
- a solver result that is not trustworthy for floating expressions must not suppress completeness recovery;
- no unconditional fallback for every exact empty set unless evidence shows it is needed.

Coverage requirement:
- one natural reproduction test;
- a deterministic family/property-style test over multiple expanded decimal quadratics `a*(x-r1)*(x-r2)` with known roots inside the domain.

### N-2 — HIGH — exact candidate validation uses literal `== 0.0`

Natural reproduction:

```text
roots((x - 1)^2 - 1e-6, x, 0, 2)
```

Expected roots: approximately `0.999` and `1.001`.

Observed audit mechanism: exact discovery finds both candidates, but substituting decimal candidates leaves tiny floating residuals. `_evaluate_root_candidate()` rejects them because it requires `float(value_quantity.magnitude) == 0.0`.

Required behavior:
- candidate validation uses a dimensionally meaningful relative residual criterion;
- exact candidates are not held to a stricter numerical residual contract than deterministic fallback candidates;
- clearly non-roots remain rejected;
- exact provenance remains `exact` when an exact-discovery candidate is validated numerically.

Coverage requirement:
- regressions for `1e-6` and `1e-12`;
- negative control demonstrating that a materially nonzero residual is not accepted.

### N-3 — HIGH — unit literal resolution is inconsistent across evaluation paths

Natural worksheet setup:

```text
L := 6*m
q := 12*kN/m
V(x) = q*(L/2 - x)
M(x) = q*x*(L-x)/2
```

Required public behavior:

```text
roots(V(x) - 6*kN, x, 0, L) -> x = 2.5 m
extrema(M(x) - 20*kN*m, x, 0, L) -> three characteristic points, including max at x = 3 m
intersections(M(x), 20*kN*m + 0*x, x, 0, L) -> valid intersections, no evaluation error
```

Audit classification:
- roots case worked in 0.9.1 and fails in 0.9.2: confirmed refactor regression;
- extrema response-literal case also failed in 0.9.1: preexisting coverage gap;
- the underlying invariant is shared.

Required architecture:
- unit literal overrides must be resolved at the public characteristic-solver boundary and propagated through all subordinate evaluation paths;
- avoid fixing isolated call sites one by one when one boundary invariant can make omission impossible;
- retain caller overrides and merge inferred direct-unit literals without mutating caller-owned dictionaries;
- roots, intersections, extrema, Piecewise subpaths, candidate evaluation and numeric fallback must observe the same resolved override context.

Coverage requirement:
- one public end-to-end test per API (`roots`, `extrema`, `intersections`);
- one lower-level test proving fallback receives/uses the resolved unit-literal context;
- inventory/audit all `evaluate_symbolic()` calls under `characteristics/` after the change.

### N-4 — LOW — symbolic extrema values can retain decidable `Abs`

Natural reproduction:

```text
a := 3*m
L := 6*m
s(x) = piecewise(x - a, x < a, 2*(x - a))
extrema(abs(s(x)), x, 0, L)
```

Numerical quantities are correct, but boundary symbolic values may display `Abs(a)` / `Abs(2*L - 2*a)` although the current numeric context determines their sign.

Required behavior:
- do not change numeric extrema semantics;
- where a symbolic value is finite and its registered scalar substitutions are known, simplify the presentation value consistently with the same context used for evaluation;
- keep Piecewise side/topology behavior unchanged.

Coverage requirement:
- natural end-to-end symbolic-value assertions for lower and upper boundaries;
- retain existing Piecewise topology regressions.

## Non-goals

- No exact-envelope implementation.
- No new SciPy dependency.
- No unrelated parser, renderer, matrix or plotting redesign.
- No broad refactor of characteristic modules beyond the minimum architectural centralization needed for N-3.
- No merge to `main` without explicit user approval.
- No Codex / Codex Cloud use without explicit user authorization.

## Verification contract

Every behavior change follows RED -> minimal GREEN -> focused regression -> full suite.

Final candidate must pass:
1. `python -m compileall -q src/engcalc_colab`.
2. New post-audit regression tests.
3. Existing characteristic acceptance/fallback/root/intersection/extrema/Piecewise integration tests.
4. Complete source suite.
5. Permanent CI matrix Python 3.10–3.14 on the pull request.
6. Real wheel build and metadata validation.
7. Clean external wheel installation with source-free full-suite execution from `site-packages`.
8. `git diff --check` / tracked-tree hygiene.
9. Idempotent rerun where temporary validation infrastructure produces no second product/test patch.
