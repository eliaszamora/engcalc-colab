# EngCalc 0.6.1 Visual Polish — Design Spec

## Scope

This release addresses two user-observed presentation regressions from the real propped-cantilever example:

1. long symbolic/numeric MathJax output still overflows or becomes visually fragmented;
2. multi-series/envelope characteristic values are shown in a summary text box instead of being attached to the actual extrema points.

No new structural-analysis mathematics is introduced. Existing 0.6.0 numerical behavior must remain unchanged.

## 1. Plot characteristic annotations

### Required behavior

- Remove the characteristic-values summary box from multi-series plots and both signed/magnitude envelopes.
- Keep extrema markers.
- Annotate the actual characteristic point near the marker.
- Annotation text must show position and ordinate only, compactly:
  - first line: `x = <value>`
  - second line: `<response symbol> = <value>`
- For magnitude envelope use `|V|`, `|M|`, etc. in the displayed ordinate label where appropriate.
- For multi-series plots each source series gets its own max/min annotations.
- If max and min are numerically identical, render one annotation, not duplicates.
- For signed envelopes annotate global algebraic maximum and global algebraic minimum.
- For magnitude envelopes annotate the global maximum magnitude only.
- The annotation must use the corresponding curve color, a small rounded white/axes-face bbox, and a light leader line.
- Annotation placement must be data-aware and axes-safe. Candidate offsets are scored to minimize collision with:
  - other characteristic annotations;
  - legend bounding region;
  - axes boundaries;
  - nearby curve samples.
- Endpoint annotations must preferentially point inward.
- Positive structural moment remains plotted downward.

### Non-goals

- No tooltips/hover in 0.6.1.
- No exact symbolic extrema yet; current plot characteristic points remain based on the existing sampled response grid.
- No public configuration switch for old panel behavior. The panel is removed from the default renderer.

## 2. Long mathematical output composition

### Problem

The current `array{lcl}` renderer splits additive terms but still allows individual terms/chains to exceed notebook width and can produce visually confusing rows such as a long equation followed by a detached continuation.

### Required behavior

Long results must switch from a single three-column chain to a block-style derivation with a stable left alignment.

#### Symbolic assignment/function result

Short form remains unchanged:

`R_A(q) = 5 q L / 8`

For a long staged operation such as `delta_B = integral(...)`, use:

- row 1: left-hand side and unevaluated operation;
- row 2+: continuation of the operation if needed;
- next row(s): evaluated symbolic result, indented and aligned under the right-hand expression.

#### `solve(...)`

If the displayed input is an equation and the complete chain is long:

- show the equation being solved as its own block;
- split the equation by complete additive terms as needed;
- show the solved assignment on a separate final row;
- never display visually ambiguous chains like `R_A(q) = expression = 0 = solution`.

#### `numeric(...)`

Long numerical evaluation must be rendered as three conceptual stages:

1. formula;
2. substituted formula;
3. final quantity.

Each stage may occupy multiple additive rows. A single additive term that is itself too wide must be recursively decomposed at safe operator boundaries (product/fraction groups) or rendered as a dedicated block row rather than overflowing.

### Width policy

- Continue using an internal visual-width estimator; lower the effective row budget for Colab-sized notebooks.
- Add a hard invariant in tests: every generated display row for representative propped-cantilever expressions must remain below the configured visual budget plus a small tolerance.
- Do not create horizontal scrolling as an intended solution.

## 3. Acceptance example

The 4 m propped cantilever remains the visual acceptance case:

- `qC = 2 tonf/m`
- `qD = 4 tonf/m`
- `qL = 3 tonf/m`
- factors `1.4`, `1.2`, `1.6`

Acceptance must cover:

- `delta_B` compatibility integral;
- `R_B(q)`, `R_A(q)`, `M_A(q)` solve output;
- long `numeric(M_UU(x0))` substitution;
- stage plots `M_C/M_D/M_L` and `V_C/V_D/V_L`;
- signed moment envelope and magnitude shear envelope.

## 4. Backward compatibility

- Preserve all 0.6.0 parser/engine APIs.
- Preserve all numerical values and units.
- Preserve single-series plot semantics, but its annotation styling may be unified with the new characteristic annotation helper.
- Preserve legends and axis labels.
- Remove only the characteristic summary panels from visual output.

## 5. Versioning

This is EngCalc 0.6.1. The previously planned numeric-ergonomics work moves to the next patch/minor slot after this visual closure.
