# EngCalc 0.7.2 — Engineering Tables Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add native pointwise engineering tables to `%%eng`, prioritizing `table(response, variable, lower, upper, count)` with unit-aware automatic discretization and supporting explicit point lists without repeated unit syntax.

**Architecture:** Preserve the restricted parser → SymPy engine → Pint numeric context → renderer/magic pipeline. Add a narrow table-specific list whitelist in the parser, immutable `TableResult` transport models, and a focused `tables.py` helper for point normalization/grid construction/evaluation so `engine.py` remains an orchestration layer. Render tables as native HTML in source order; do not add pandas or general Python list support.

**Tech Stack:** Python 3.10+, SymPy, Pint, Matplotlib (existing plots only), IPython/Jupyter magic, pytest, stdlib.

**Spec:** `docs/superpowers/specs/2026-08-29-engcalc-v0.7.2-engineering-tables-design.md`

## Global Constraints

- Start implementation from canonical EngCalc **0.7.1** `main` baseline.
- Primary syntax: `table(M(x), x, 0, L, 21)`.
- Explicit unit-once syntax: `table(M(x), x, [0, 1, 2], m)`.
- Fully explicit compatible quantities remain supported: `table(M(x), x, [0*m, 50*cm, 1*m])`.
- Exact dimensionless zero may inherit the compatible dimensional endpoint/point unit; nonzero dimensionless values may not silently inherit a dimensional unit.
- Descending uniform ranges are valid and preserve source order.
- Uniform `count` is dimensionless integer and `count >= 2`.
- Multiple response expressions must be dimensionally compatible in 0.7.2 and preserve source-column order.
- Table evaluation must not mutate symbolic or numeric state, including a pre-existing numeric value for the table variable.
- Arbitrary list literals remain rejected outside the explicit table-point position and existing plot/envelope sweep positions.
- No CSV/Excel export, pandas dependency, interactive spreadsheet, arbitrary styling kwargs, Cartesian table sweeps, cross-dimension tables, piecewise support, or derivation traces in 0.7.2.
- Preserve all 0.7.1 behavior, including plot/envelope syntax, 201-point plot sampling and positive structural moment downward.
- TDD is strict RED → minimal GREEN → focused regression → full source regression.
- Do not manually invoke Codex, `@codex review`, Codex Cloud, or any operation that may consume Codex quota without explicit authorization.
- Version bump occurs only during release closure.
- Do not merge without explicit user approval.

- [ ] **Step 3: Implement normalization without changing plot semantics**

`tables.py` should use Pint quantities from the existing `NumericContext`. Do not weaken `NumericContext.normalize_plot_bounds`, because plots intentionally keep their current ascending-range contract. Table-specific rules live in the new module.

Uniform algorithm:

```python
lower = context._as_quantity(lower)
upper = context._as_quantity(upper)
# promote only exact dimensional zero when the peer endpoint is dimensional
# convert upper to lower/canonical units
# validate count as exact dimensionless integer >= 2
step = (upper - lower) / (count - 1)
return tuple(lower + index * step for index in range(count))
```

Explicit-list algorithm:

- with declared unit: dimensionless magnitudes become quantities in that unit; dimensional points convert to it;
- without declared unit: first dimensional point establishes canonical unit; exact zero may be promoted; nonzero dimensionless mixed with dimensional input is an error;
- all dimensionless values stay dimensionless.

Use public/internal helpers conservatively; if `_as_quantity` access would create an undesirable cross-module contract, expose a small `NumericContext.as_quantity()` wrapper and test it instead of duplicating Pint detection logic.

```python
import pytest

from engcalc_colab.engine import EngineeringEngine
from engcalc_colab.errors import EngEvaluationError
from engcalc_colab.models import TableResult
from engcalc_colab.parser import parse_cell


def eval_cell(engine, source):
    return [engine.evaluate(stmt) for stmt in parse_cell(source)]


def test_uniform_table_evaluates_multiarg_response_at_exact_count():
    engine = EngineeringEngine()
    eval_cell(engine,
        "M(x, q, L) = q*x*(L-x)/2\n"
        "q := 4*kN/m\n"
        "L := 5*m")
    result = eval_cell(engine, "table(M(x, q, L), x, 0, L, 21)")[-1]
    assert isinstance(result, TableResult)
    assert len(result.point_values) == 21
    assert result.point_values[10].to("m").magnitude == pytest.approx(2.5)
    assert result.columns[0].values[10].to("kN*m").magnitude == pytest.approx(12.5)


def test_multiple_table_responses_preserve_source_order_and_common_dimension():
    engine = EngineeringEngine()
    eval_cell(engine,
        "M_D(x) = qD*x*(L-x)/2\n"
        "M_U(x) = qU*x*(L-x)/2\n"
        "qD := 4*kN/m\nqU := 8*kN/m\nL := 5*m")
    result = eval_cell(engine, "table(M_D(x), M_U(x), x, 0, L, 3)")[-1]
    assert [column.display_label for column in result.columns] == ["M_D(x)", "M_U(x)"]


def test_table_locally_overrides_but_does_not_mutate_stored_x():
    engine = EngineeringEngine()
    eval_cell(engine, "f(x) = x\nx := 9*m\nL := 2*m")
    eval_cell(engine, "table(f(x), x, 0, L, 3)")
    assert engine.numeric_context.get("x").to("m").magnitude == pytest.approx(9)
```

- [ ] **Step 3: Parse the table call semantically in the engine**

Engine responsibilities:

1. identify mode from the AST shape;
2. require table variable to be `ast.Name`;
3. identify all preceding response nodes;
4. resolve uniform endpoints/count or explicit points through the numeric context + `tables.py`;
5. expand user-function calls with the existing symbolic evaluator so multi-argument/nested functions retain 0.7.1 semantics;
6. evaluate each symbolic response at every table point using `numeric_context.evaluate_symbolic(..., overrides={variable: point})`;
7. normalize each column to its first result unit;
8. verify subsequent response columns are dimensionally compatible with the first response family;
9. return immutable `TableResult`.

- [ ] **Step 4: Preserve dimensional zero in response columns**

Do not evaluate table rows by naive SymPy substitution followed by simplification if that can erase units at zeros. Use the same Pint-backed `evaluate_symbolic` path used by plots so boundary zeros remain quantities in the response unit family.
