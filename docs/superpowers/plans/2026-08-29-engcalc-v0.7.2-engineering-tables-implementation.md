# EngCalc 0.7.2 — Engineering Tables Implementation Plan

**Goal:** Add native engineering tables to `%%eng`, centered on `table(response, variable, lower, upper, count)` with unit-aware automatic discretization, plus explicit point lists with a unit declared once.

**Spec:** `docs/superpowers/specs/2026-08-29-engcalc-v0.7.2-engineering-tables-design.md`

**Architecture:** Preserve parser → SymPy engine → Pint numeric context → renderer/magic. Keep arbitrary lists forbidden. Add a narrow table-list parser context, immutable table result models, and a focused `tables.py` module for table point normalization/evaluation. Do not alter plot range semantics to support descending table ranges.

## Global constraints

- Baseline is released EngCalc 0.7.1.
- Strict RED → GREEN TDD; no production behavior before a failing test.
- Primary form: `table(M(x), x, 0, L, 21)`.
- Unit-once form: `table(M(x), x, [0, 1, 1.5, 2], m)`.
- Fully explicit compatible quantities remain supported.
- Exact dimensionless zero may inherit a compatible dimensional peer; nonzero dimensionless values may not.
- Descending uniform ranges are valid.
- `count` is a dimensionless integer >= 2, including both endpoints.
- Multiple response columns preserve source order and must be dimensionally compatible in 0.7.2.
- Table evaluation never mutates symbolic or numeric state.
- Native HTML output inside `%%eng`; no pandas/runtime dependency.
- General Python list syntax remains rejected.
- Preserve plot/envelope 201-point sampling and positive-moment-down convention.
- Version bump only at release closure.
- Do not invoke Codex or consume Codex quota without explicit user authorization.
- Do not merge without explicit user approval.

## Task 1 — Restricted grammar and result models

**Files:** `parser.py`, `models.py`, new `tests/test_table_parser.py`.

RED contracts first:
- accept `table(M(x), x, 0, L, 21)`;
- accept `table(M(x), x, [0,1,2], m)`;
- accept fully explicit point list;
- reserve `table` as an identifier;
- reject empty/nested/comprehension lists;
- continue rejecting list literals outside approved table/plot/envelope positions.

GREEN implementation:
- add `table` to allowed/reserved calls;
- do not add `ast.List` globally;
- validate table AST with a dedicated helper;
- add immutable `TableColumn(display_label, unit, values)` and `TableResult(statement, variable, point_unit, point_values, columns, mode)`.

Focused gate: new parser tests + existing parser and plot-parser tests.

## Task 2 — Point/range normalization

**Files:** new `tables.py`, new `tests/test_table_points.py`.

RED contracts:
- `0` + `5*m` with count 3 → `[0,2.5,5] m`;
- descending `5*m` → `0*m` works;
- nonzero dimensionless + dimensional endpoint rejects;
- declared-unit magnitudes work;
- mixed `m`/`cm` explicit points normalize;
- all-dimensionless points work;
- incompatible points reject;
- count 1, fractional count, or dimensional count reject.

GREEN implementation:
- table-specific normalization in `tables.py`;
- reuse Pint/NumericContext quantity semantics without weakening `normalize_plot_bounds`;
- generate exactly count points, preserving direction and endpoints.

Focused gate: table-point tests + numeric-context + plot-engine regression.

## Task 3 — Engine evaluation

**Files:** `engine.py`, `tables.py`, optional `errors.py`, new `tests/test_table_engine.py`.

RED contracts:
- multiarg response: q=4 kN/m, L=5 m, 21 points gives midpoint x=2.5 m and M=12.5 kN·m;
- multiple compatible responses preserve order;
- explicit unit-once and mixed-unit points work;
- constant, nested-user-function and scalar-math responses work;
- pre-existing numeric `x` is locally overridden and restored;
- unresolved non-table symbols produce targeted error;
- incompatible response dimensions reject;
- invalid variable/call shape/count and assigned table reject.

GREEN implementation:
- `_Evaluator` dispatches `table(...)`;
- resolve response expressions with existing user-function semantics;
- evaluate rows through `NumericContext.evaluate_symbolic(..., overrides={variable: point})` to preserve dimensional zero;
- normalize response values to one compatible response unit family;
- construct `TableResult` without mutating state.

Focused gate: table engine + multiarg + plot + diagnostics regressions.

## Task 4 — HTML rendering and magic source order

**Files:** `renderer.py`, `magic.py`, new `tests/test_table_rendering.py`, extend `tests/test_magic.py`.

RED contracts:
- units appear once in headers, not every cell;
- precision and zero tolerance match `RenderSettings`;
- dimensionless columns omit unit suffix;
- values/labels are escaped safely;
- source order for equation → table → equation is `[Math, HTML, Math]`;
- headings coexist correctly.

GREEN implementation:
- add `render_table` with compact scoped HTML/CSS;
- variable column first, response columns in source order;
- flush pending MathJax group before a `TableResult`, display HTML, then resume.

Focused gate: table rendering + magic + renderer regressions.
