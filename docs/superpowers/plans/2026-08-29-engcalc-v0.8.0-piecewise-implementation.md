# EngCalc 0.8.0 Piecewise Expressions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add safe, unit-aware Piecewise expressions to EngCalc, fully integrated with symbolic evaluation, `numeric`/`result`, tables, plots/envelopes, calculus, rendering and release validation.

**Architecture:** Use SymPy `Piecewise`/relational objects as the symbolic source of truth, but keep EngCalc responsible for restricted grammar, Pint-aware comparison/evaluation, dimensional-zero handling, explicit-breakpoint extraction, plot segmentation and engineering-facing diagnostics. Add a focused `piecewise.py` helper module rather than expanding all Piecewise responsibilities inside `engine.py`.

**Tech Stack:** Python 3.13, `ast`, SymPy, Pint, Matplotlib, IPython/MathJax, pytest.

**Spec:** `docs/superpowers/specs/2026-08-29-engcalc-v0.8.0-piecewise-design.md`

## Global Constraints

- Canonical product baseline is EngCalc 0.7.2 on `main`.
- Keep package/runtime version at `0.7.2` until the release-closing task.
- No new runtime dependency.
- Strict TDD: every new behavior starts RED, then minimal GREEN.
- Preserve all existing 0.7.2 behavior, including multi-argument functions, generalized partial evaluation, tables, plotting/envelopes, source ordering, precision/zero tolerance and positive structural moment plotted downward.
- Piecewise uses one interval variable per `piecewise(...)` call.
- Only `<`, `<=`, `>`, `>=` are accepted in Piecewise conditions; comparisons remain invalid outside the Piecewise condition whitelist.
- Conditions must compare the interval variable directly against an expression that does not contain that variable.
- Default branch is mandatory.
- Exact dimensionless zero may inherit compatible dimensional units; nonzero dimensionless values may not silently mix with dimensional quantities.
- `table(..., count)` keeps exactly `count` points. Breakpoints never add table rows.
- Plot/envelope keeps the 201-point base grid and augments it with exact resolvable Piecewise breakpoints.
- Plot lines must split at Piecewise transitions; do not draw a fictitious connector across a jump.
- No automatic `DiracDelta`, no invented derivative value at a Piecewise breakpoint.
- Do not invoke Codex or anything that can consume Codex quota without explicit user authorization.
- Retain planning/feature branches unless explicitly asked to delete them.
