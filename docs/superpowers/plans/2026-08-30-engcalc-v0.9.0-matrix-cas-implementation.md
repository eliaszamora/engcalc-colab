# EngCalc 0.9.0 Matrix/CAS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add MATLAB/TI-Nspire-style vectors, matrices and exact linear-system solving to `%%eng`, with one-based indexing, SymPy exact algebra, Pint-aware numerical evaluation per matrix entry, engineering diagnostics and native MathJax rendering.

**Architecture:** Keep matrix expressions symbolic-first. Parse EngCalc matrix syntax before restricted Python AST evaluation, construct immutable SymPy matrices, perform algebra/solve symbolically, and evaluate final scalar cells through the existing `NumericContext`. `QuantityMatrix` is an immutable numerical output boundary, not a second public algebra engine. Existing table/sweep bracket collections stay contextual and unchanged.

**Tech Stack:** Python >=3.10; validation target Python 3.13; `ast`; SymPy >=1.13; Pint >=0.24; IPython/MathJax; pytest >=8. No new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-08-30-engcalc-v0.9.0-matrix-cas-design.md`

**Normative clarification:** `docs/superpowers/specs/2026-08-30-engcalc-v0.9.0-matrix-cas-numeric-semantics-clarification.md`

## Global Constraints

- Canonical implementation baseline is EngCalc 0.8.0 on `main@9b90014fa59014eb9e831c71c7f7f2a35dfeb86d` unless `main` has intentionally advanced before execution; any advance must be audited before branching.
- Known complete baseline is **557/557 GREEN**.
- Keep package/runtime version at **0.8.0** until the release-closing task.
- Do not add NumPy, SciPy, pandas, or any other runtime dependency for the core 0.9.0 matrix subsystem.
- Strict RED -> GREEN TDD for every new product behavior.
- No production work directly on `main` or `planning/v0.9.0-matrix-cas`; execution uses `feature/v0.9.0-matrix-cas` created from the current audited `main`.
- Never invoke Codex / `@codex review` / Codex Cloud without explicit user authorization.
- Never merge the implementation PR without explicit user approval.
- `%%eng` remains a restricted DSL; ordinary Python remains outside the cell magic.
- Canonical matrix syntax is `[a, b; c, d]`; comma separates columns, semicolon separates rows.
- Row vector `[a, b]` has shape `1 x 2`; column vector `[a; b]` has shape `2 x 1`.
- Vectors are matrices; do not introduce mandatory public `vector()` or `row()` constructors.
- Indexing is one-based.
- `A*B` is matrix multiplication. Do not introduce element-wise multiplication, broadcasting, or NumPy semantics.
- Symbolic truth is immutable SymPy matrix algebra.
- Numerical/unit truth remains Pint-backed and is evaluated per scalar matrix cell.
- Heterogeneous physical dimensions inside one matrix are first-class.
- `QuantityMatrix` is output-only/private numerical infrastructure; do not implement arithmetic methods that create a parallel public matrix algebra.
- `solve(A,b)` returns an exact symbolic column matrix and does not silently fall back to floating-point NumPy solving.
- Existing scalar `solve(eq,x)`, Piecewise, table, plot, envelope, narrative, multi-argument functions, precision/zero tolerance and positive-moment-downward plotting remain regression requirements.
- Existing `table(...,[...])` point lists and plot/envelope sweep lists remain collections, not row matrices.
- Matrix-valued persistent `:=`, sparse/FEM workflows, generalized eigenproblems, slicing, block matrices, pseudoinverse, SVD and element-wise array operations remain deferred.
- LU/QR/Cholesky are optional in the approved design. This core 0.9.0 plan deliberately defers them to a later matrix follow-up so they cannot block the mandatory release contract.
