# EngCalc 0.6.1 Visual Polish — Implementation Plan

## Goal

Deliver a visually cleaner EngCalc 0.6.1 without changing engineering results: point-attached characteristic annotations replace summary panels, and long MathJax derivations render as bounded, readable blocks.

## TDD Task 0 — Baseline and fixture

Files:
- `tests/test_plotting.py`
- `tests/test_renderer.py`
- optional dedicated `tests/test_visual_polish_v061.py`

Steps:
1. Run the current full suite on the feature branch and record baseline count.
2. Add a shared propped-cantilever fixture/source representative of the user screenshots.
3. Do not change production until RED tests are observed.

## TDD Task 1 — Multi-series point annotations

RED tests must assert:
- multi-series plots have no characteristic summary `axis.text` panel;
- each series' distinct extrema produce annotation artists attached to the exact data point;
- annotation text contains `x =` and the response ordinate label/value;
- coincident max/min produces one annotation;
- legend remains present;
- moment axis remains inverted.

Production changes:
- remove `_characteristic_panel_text`, panel footprint/corner helpers from the multi-series path;
- generalize `_annotate_extreme` into a reusable characteristic-point annotation helper;
- add collision-aware offset selection over a fixed candidate set.

GREEN gate:
- focused plotting tests;
- full suite.

## TDD Task 2 — Envelope point annotations

RED tests must assert:
- signed envelope has no summary panel and has exactly the characteristic max/min annotations;
- magnitude envelope has no summary panel and has exactly one global magnitude annotation;
- annotation `xy` equals the governing sampled coordinate;
- magnitude annotation displays `|<response>|` and not the old `Magnitude envelope` panel text;
- source curves remain faint and excluded from legend.

Production changes:
- remove `_envelope_characteristic_panel_text`, `_magnitude_envelope_characteristic_panel_text`, and panel calls;
- use the shared point-annotation helper after lines/legend/axis inversion are established.

GREEN gate:
- focused envelope tests;
- full suite.

## TDD Task 3 — Long symbolic block renderer

RED fixtures:
- `delta_B = integral((-q*(L-s)^2/2 + R_B_aux*(L-s))*(L-s), s, 0, L)`;
- `R_B(q) = solve(eq(delta_B, 0), R_B_aux)`;
- `R_A(q) = solve(eq(R_A_aux + R_B(q) - q*L, 0), R_A_aux)`;
- `M_A(q) = solve(eq(M_A_aux + q*L^2/2 - R_B(q)*L, 0), M_A_aux)`.

RED assertions:
- long staged results generate separate operation/result blocks;
- long solve does not render `lhs = equation = solution` in one row;
- every row satisfies visual width budget tolerance;
- short symbolic expressions remain one row.

Production changes in `renderer.py`:
- introduce row/block helpers that return semantic stages;
- lower row budget for notebook-safe output;
- recursively split overly wide additive expressions; if an individual term remains too wide, split safe multiplicative/fraction subgroups into continuation rows rather than overflow;
- preserve `array{lcl}` only when short; use a left-aligned block/array composition for long results.

GREEN gate:
- focused renderer tests;
- full suite.

## TDD Task 4 — Long numeric substitution renderer

RED fixture:

RED assertions:
- formula, substitution and final result are distinct stages;
- substituted stage can span several bounded rows;
- no generated row exceeds width budget tolerance;
- final numeric quantity and units are unchanged.

Production changes:
- reuse block-stage helpers for `NumericEvaluationResult` and `PartialNumericEvaluationResult`;
- no changes to numeric engine.

GREEN gate:
- focused numeric-render tests;
- full suite.

## TDD Task 5 — Visual acceptance artifact

Create a temporary GitHub Actions validation workflow on the feature branch that:
1. installs branch source;
2. runs the complete propped-cantilever `%%eng` flow;
3. saves MathJax/LaTeX output and four PNGs:
   - stage moments `M_C/M_D/M_L`;
   - stage shears `V_C/V_D/V_L`;
   - signed moment envelope;
   - magnitude shear envelope;
4. uploads evidence artifact.

Acceptance checks:
- no characteristic summary panel artists;
- annotations remain inside figure canvas;
- annotations point to their exact extrema coordinates;
- long renderer rows pass width invariants;
- 21-station envelope numerical regression remains unchanged.

## Definition of done

- No characteristic-value summary boxes remain in multi-series or envelope renderers.
- Characteristic values are communicated at the relevant data points with x-position and response magnitude.
- Representative long symbolic/numeric calculations do not overflow the renderer's notebook width budget.
- Existing engineering results remain unchanged.
- Full source and installed-wheel suites pass.
- Visual evidence from the Excel/propped-cantilever example is available.
- `CURRENT.md` is sufficient to resume from a new conversation without reconstructing context.
